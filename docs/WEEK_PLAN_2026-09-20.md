## Research track - existing data only

Baseline remains the currently accepted mean-reversion strategy with BUY LIMIT at 97% of signal-day close.

### Test A - broader candidate pool at the close

Use the existing ten-year daily OHLCV dataset.

For every historical signal date:
- generate all valid strategy candidates before truncating to available position slots;
- retain the existing strategy ranking;
- define next-session fill outcome as whether the next eligible session Low reaches the 97% limit;
- test rules for selecting the available slots from a broader candidate pool using only information available at the close;
- compare against the existing baseline selection.

Required metrics:
- total return / CAGR;
- max drawdown;
- Sharpe where meaningful;
- number of candidate signals;
- number and percentage of filled BUYs;
- average/median idle cash;
- capital utilization;
- number of days with unused position slots;
- return on total capital, not only return on filled trades.

The purpose is not to optimize a new strategy immediately but to determine whether candidate selection can improve capital utilization while preserving the 97% entry edge.

### Test B - after-hours candidate selection

Do not buy new Massive data this week.

First inspect the already-preserved Massive/local historical files to determine whether extended-hours/minute/trade data are already present for any useful period. If sufficient after-hours history is not already available locally, document the test design and defer empirical execution until the new PC/research environment is ready and a future data decision is made.

Do not substitute next-day Open or other future information for genuine after-hours observations.

## LIVE transition track

LIVE use requires an explicit implementation and acceptance gate separate from PAPER.

### Capital/risk constraints

- Hard LIVE strategy capital ceiling: EUR 10,000 equivalent.
- No leverage.
- No short selling.
- Existing long-only order-safety guard remains mandatory.
- Existing max-position and duplicate-order controls remain mandatory.
- The LIVE cap must be enforced in code independently of account BuyingPower and independently of total account Net Liquidation Value.
- The LIVE cap must not be increased automatically.
- Any later increase requires a separate operator decision.

### PAPER vs LIVE comparison

For every LIVE planned/submitted order, preserve the same decision inputs and record:
- signal session;
- planned symbol/side/order type/limit;
- planned quantity under the LIVE cap;
- broker submission timestamp;
- acknowledgement timestamp;
- first fill timestamp;
- final fill timestamp;
- filled quantity / partial-fill history;
- average fill price;
- commissions/fees;
- slippage relative to the limit and/or contemporaneous reference price;
- unfilled/expired orders;
- realized P&L when closed.

Compare against the prior PAPER history and, where technically practical without risking duplicate exposure, a shadow PAPER/simulation record generated from the identical strategy plan. The comparison must distinguish:
- fill probability;
- partial fills;
- time-to-fill;
- commissions;
- slippage;
- order rejection;
- execution latency;
- realized P&L differences.

### Required acceptance sequence before first LIVE automated BUY

1. Inspect LIVE account connectivity/configuration without broker mutation.
2. Add an explicit LIVE-cap configuration and fail-closed account-mode validation.
3. Verify that PAPER and LIVE identities/channels cannot be confused in Telegram, console, logs or reports.
4. Run startup/preflight in LIVE read-only mode.
5. Prove operational buy budget cannot exceed the EUR 10,000-equivalent cap even if IBKR BuyingPower/AvailableFunds are much larger.
6. Re-run long-only, duplicate-order, max-position, stale-data and account-mode safety tests.
7. Controlled LIVE acceptance with the smallest practical position/order size.
8. Only after that controlled acceptance, allow the normal automated strategy to operate under the hard EUR 10,000-equivalent ceiling.
9. Preserve PAPER/LIVE execution comparison reports for review before any capital increase.
